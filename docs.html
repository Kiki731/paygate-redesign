Accept a card payment

Charge Visa, Mastercard and Verve cards from your own checkout. You build and encrypt the card details, PayGate runs 3-D Secure, and the customer comes back to your site with a result.

8 min readUpdated 12 Nov 2026Server-side integration

Payment linksCreate a link in the dashboard and share it on WhatsApp or email.No code Hosted checkoutSend customers to a PayGate page for card, transfer and NQR.Low code · recommended Direct card APICollect card details in your own form and call the API.Full control · PCI DSS needed

Before you begin

  1. Create a merchant account on the PayGate dashboard and complete your business profile.
  2. Wait for our team to approve your profile. You’ll get an email when your account is active.
  3. In the dashboard, open Settings → API keys. Copy your merchantId, API username and password, and your secret key.
Your servers will see card numbers. On this route the card number and CVV pass through your system, so you must be PCI DSS compliant. If you’re not, use hosted checkout: we collect the card for you.
Keep your secret key on your server only. Never put it in a mobile app, a browser script or a public repository.

Authentication

Every request uses HTTP Basic authentication with the API username and password from your dashboard. Send JSON, and accept any response type.

  • Authorizationheaderrequired

    Basic followed by your username and password, base64-encoded.

  • Content-Typeheaderrequired

    Always application/json.

curl https://thirdparty.paygate.upperlink.ng/... \
  -u "$PAYGATE_USERNAME:$PAYGATE_PASSWORD" \
  -H "Content-Type: application/json"
const auth = Buffer.from(
  `${process.env.PAYGATE_USERNAME}:${process.env.PAYGATE_PASSWORD}`
).toString("base64");

const headers = {
  Authorization: `Basic ${auth}`,
  "Content-Type": "application/json",
};

1Build the card payload

Put the card and payer details in a JSON object. Every field is a string.

  • payGateRefstringrequired

    Your unique reference for this payment. Use it to find the payment later.

  • cardNumberstringrequired

    The card number, digits only.

  • expirationMonthstringrequired

    Two digits, for example 12.

  • expirationYearstringrequired

    Two digits, for example 30.

  • securityCodestringrequired

    The CVV on the back of the card.

  • amountstringrequired

    The amount to charge, in major units (100 is ₦100.00). unit to confirm

  • currencystringrequired

    An active currency code such as NGN or USD. Get the list from Currencies.

  • countryCodestringrequired

    The payer’s country, for example NG. Get the list from Countries.

  • emailstringrequired

    The payer’s email address. We send the receipt here.

card-payload.json
{
  "payGateRef": "ORDER-10294",
  "cardNumber": "4456530000000007",
  "expirationMonth": "12",
  "expirationYear": "30",
  "securityCode": "123",
  "amount": "45000",
  "currency": "NGN",
  "countryCode": "NG",
  "email": "chiamaka@example.com"
}

2Encrypt it with your secret key

Encrypt the JSON string with AES, using AES/ECB/PKCS5Padding and the secret key from your dashboard. Base64-encode the result. This string is the data field in the next step.

Encrypt in memory and send straight away. Don’t store or log the plain payload, even in debug logs.
import crypto from "node:crypto";

export function encryptPayload(payload, secretKey) {
  const key = Buffer.from(secretKey, "utf8");
  // aes-128/192/256-ecb, matching your key length
  const cipher = crypto.createCipheriv(`aes-${key.length * 8}-ecb`, key, null);
  return Buffer.concat([
    cipher.update(JSON.stringify(payload), "utf8"),
    cipher.final(),
  ]).toString("base64");
}
function encryptPayload(array $payload, string $secretKey): string {
    $cipher = 'AES-' . (strlen($secretKey) * 8) . '-ECB';
    // OPENSSL_RAW_DATA then base64 = PKCS5 padding, base64 output
    $raw = openssl_encrypt(json_encode($payload), $cipher, $secretKey, OPENSSL_RAW_DATA);
    return base64_encode($raw);
}
public static String encryptPayload(String json, String secretKey) throws Exception {
    SecretKeySpec key = new SecretKeySpec(secretKey.getBytes(UTF_8), "AES");
    Cipher cipher = Cipher.getInstance("AES/ECB/PKCS5Padding");
    cipher.init(Cipher.ENCRYPT_MODE, key);
    return Base64.getEncoder().encodeToString(cipher.doFinal(json.getBytes(UTF_8)));
}

3Call payerAuth

Send the encrypted data with the payer’s details to the transaction endpoint. The response gives you an authUrl for 3-D Secure.

POST /transaction

  • datastringrequired

    The encrypted card payload from step 2.

  • merchantIdstringrequired

    Your merchant ID from the dashboard.

  • firstName, lastNamestringrequired

    The payer’s name as it appears on the card.

  • phonestringrequired

    The payer’s phone number, for example 08031234567.

  • address, city, statestringrequired

    The payer’s billing address.

  • redirectUrlstringrequired

    Where we send the customer, with the result, after 3-D Secure.

  • consent"1" | "0"required

    1 if the customer agreed to save the card for future payments, otherwise 0.

  • splitCodestringoptional

    Share this payment using a split rule from your dashboard.

  • accountCodestringoptional

    Settle this payment to a separate settlement account.

  • subMerchantCodestringaggregators only

    The sub-merchant this payment belongs to. We issue these codes to aggregators.

4Send the customer to 3-D Secure

Open authUrl in the customer’s browser. Their bank asks them to confirm the payment with an OTP, a PIN or their banking app. Cards that don’t need 3-D Secure complete straight away.

Afterwards we send the customer to your redirectUrl with the transaction reference and status.

server.js
// after payerAuth succeeds
return res.redirect(303, authUrl);

5Confirm the result before you give value

The redirect tells you how the payment went, but a customer could change the address. Check the transaction status from your server, and only release goods or credit an account when the code is 00.

A status-query endpoint isn’t in the current docs. endpoint and webhook details to confirm
server.js
app.get("/paid", async (req, res) => {
  const status = await paygate.getStatus(req.query.reference); // illustrative
  if (status.code === "00") await fulfilOrder(status.payGateRef);
  res.render("result", { status });
});

Response codes

Every transaction ends in one of these codes.

CodeStatusWhat to do
00SuccessfulGive value. The money is on its way to you.
01PendingWait, then check the status again. Don’t charge twice.
04ProcessingThe bank is still working on it. Check again shortly.
02FailedAsk the customer to try again or use another card.
06DeclinedThe bank refused it. Ask for another card.
07CanceledThe customer stopped the payment. Nothing was charged.
